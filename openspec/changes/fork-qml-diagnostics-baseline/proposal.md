# Give the fork its own QML diagnostics baseline

## Why

`scripts/qmllint_report.py --check` gates the build against
`qml-diagnostics-baseline.json`, which records, per file, the `unqualified`
warnings that are allowed — files at zero are locked at zero, files above carry a
ceiling that may only fall (see the `qml-diagnostics` capability).

That baseline describes **upstream's** QML tree, not the fork's. It was last
regenerated by an upstream commit:

```
01d77ba2 2026-07-30  Root pages at QtQuick.Templates.Page to restore AOT compilation (#1715)
```

and its shape proves the provenance:

- `ceilings: {}` — **zero** files with any `unqualified` residue. That is true of
  upstream's tree (post its singleton migration) and cannot be true of the fork,
  which adds a whole barista UI.
- `clean: [219 files]` — upstream's file set, none of the fork's barista QML among
  them.

Every fork sync re-imports this file verbatim (it is a textually-clean auto-merge
of a generated registry — the same class of trap as the migration chain and the
`qmlRegister`/widget-catalog registries: clean to `git`, wrong for the fork). So
on a clean fork desktop build the gate **cannot pass**, and has not since at least
the 2026-07-30 sync. It surfaces now only because the fork ships Android APKs
(`build.sh` forces the gate's platform off) and develops on Windows; the
2026-08-01 upstream sync ran the first clean macOS desktop build in a while and
the gate failed. The sync did not touch the baseline — `git diff` over the merge
range shows it unchanged.

What the gate reports, and what each item actually is:

| Gate message | Files | Reality |
|---|---|---|
| "not in the `qt_add_qml_module` list" | `assistant/avatars/AvatarFace.qml`, `AvatarOrb.qml` | Fork-only files genuinely unregistered (grep of `CMakeLists.txt` = 0). Two of four avatars in that fork dir. |
| "new QML file … must be clean" | `BaristaChipRow`, `BaristaEditDialog`, `TempPickerDialog`, `layout/items/BaristaItem` | Registered in the module (grep ≥ 1), but **absent from the baseline** — added to the fork after upstream last regenerated it, so the gate treats them as new. |
| "N unqualified in a file that had none" | `main.qml` (11), `IdlePage` (3), `BrewDialog` (1), `PostShotReviewPage` (9), `SettingsHistoryDataTab` (7) | Files upstream baselines at 0, carrying fork edits that add unqualified accesses — or accesses to fork types the run under-resolved. |
| category not exempt | `Quick.layout-positioning` (8), `missing-property` (6), `required` (1), `unresolved-type` (4) | `unresolved-type` in particular is the fingerprint of types that did not resolve — consistent with the unregistered/unbaselined fork QML above. |

The blast radius includes `tst_qmlregistration`, which reads the `Decenza.qmltypes`
the app QML build produces: because the gate fails that build, the qmltypes is
stale and the test reports `BaristaStorage`/`LiveShotCoach` "absent" even though
both are correctly declared `FINAL` in `maincontroller.h`. Fixing the gate clears
that test as a side effect.

## What Changes

- **Register the two unregistered fork avatar files** (`AvatarFace.qml`,
  `AvatarOrb.qml`) in `qt_add_qml_module`, or record them in
  `NOT_IN_MODULE_BY_DESIGN` in `scripts/qmllint_report.py` if they are deliberately
  excluded — the gate demands one or the other.
- **Resolve the fork's genuine `unqualified` accesses** in the barista QML and the
  fork edits to shared files, the same way upstream cleared its own: make the
  identifier resolvable (singleton/type registration), not silence it. Per the
  `unqualified`-never-exempt requirement, new files (the barista components) must
  reach zero; the only residue allowed to carry a per-file ceiling is the
  delegate-scope kind (`modelData`/`root`/`index`), whose remedy is
  `pragma ComponentBehavior: Bound`.
- **Regenerate `qml-diagnostics-baseline.json` on the fork tree** with
  `--update-baseline`, from a build the script certifies as fully resolving — its
  own `#1680` guard refuses to update from an under-resolving run, and that guard
  must be honoured, not overridden with `--allow-stale`.
- **ADD a capability requirement** that the baseline reflects the tree it gates, so
  an upstream sync that replaces it is resolved by regenerating on the fork tree —
  never by taking upstream's copy — closing the recurring merge tax.

## Impact

- Affected specs: `qml-diagnostics` (one ADDED requirement; the existing
  requirements are unchanged and already describe the per-file/clean-list machinery
  this relies on).
- Affected code: `CMakeLists.txt` (`qt_add_qml_module` avatar entries),
  `scripts/qmllint_report.py` (`NOT_IN_MODULE_BY_DESIGN` if avatars are by-design),
  `qml-diagnostics-baseline.json` (regenerated on the fork tree), and whichever
  fork QML files carry resolvable `unqualified` accesses (`main.qml`,
  `PostShotReviewPage.qml`, the barista components, …).
- Unblocks a clean fork desktop build and clears `tst_qmlregistration` (both
  subtests) as collateral — see the pre-existing-failure catalogue this change is
  drawn from.

### Deliberately NOT in scope

- **The delegate-scope `unqualified` residue** (`modelData`/`root`/`index` under
  `ComponentBehavior: Bound`). Upstream carries this as recorded per-file counts,
  not as fixes; the fork should record its own the same way and schedule it
  separately, exactly as the `qml-diagnostics` "Residual Scope Diagnostics"
  requirement intends. Do not fold it into a category exemption to reach green.
- **Weakening the gate.** Not `--allow-stale` on the update, not adding
  `unqualified` to the category exemption list, not per-line disables. The gate
  exists because an undeclared QML identifier compiles clean and throws only when
  its binding first evaluates — the exact defect that shipped in 2.0.1 (#1661). The
  problem here is a baseline that describes the wrong tree, not a gate that is too
  strict.
- **The other five pre-existing clean-build failures** (barista cue-text drift,
  `locationprovider.cpp` legacy store, coffee-KB reasoning, three test files
  missing `QTest::failOnWarning()`, the `pause_turn` timeout). Unrelated causes;
  their own cleanup.
